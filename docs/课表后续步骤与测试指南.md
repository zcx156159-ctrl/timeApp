## 4. 注册 / 登录测试流程

### 4.1 注册并首次同步

1. 打开 `http://127.0.0.1:8080/`
2. 点顶栏 **“同步”**
3. 账号区输入：
   - 邮箱/手机号：如 `test@example.com`
   - 密码：**至少 6 位**（如 `123456`）
4. 点 **“注册”** → 状态应显示 **“已注册并登录”**
5. 关闭对话框，添加几门课（新增/导入示例均可）→ 状态应自动变为 **“已同步”**
6. 验证数据落库：查看服务器目录 `timetable-v2.db` 已生成（或再登录一次确认数据在）

### 4.2 双端同步验证

1. 打开**第二个浏览器**（或隐身窗口），访问同一地址
2. “同步”→ 输入**同一账号密码** → 点 **“登录”**
3. 应看到与第一个浏览器一致的课表（自动拉取）
4. 在 A 端**删除**一门课 → B 端点“同步”里的 **“立即同步”** → 该课在 B 端消失
5. 在 B 端**修改**某门课时间 → A 端重启或立即同步 → 修改生效

### 4.3 退出与重登

1. “同步”→ 账号区点 **“退出”** → 状态“未登录”
2. 再点 **“登录”** → 数据恢复（令牌持久化）

### 4.4 常见问题

| 现象 | 原因/解决 |
|------|-----------|
| 注册提示“密码至少 6 位” | 密码长度不足 |
| 注册提示“请填写有效邮箱或手机号” | 邮箱缺 `@` 或手机号格式不对 |
| 注册提示 400/重复 | 该邮箱已注册 → 直接改用“登录” |
| 同步失败/登录失败 | 后端没跑；Web 端服务器地址留空（同源），桌面端填 `http://127.0.0.1:8080` |
| 登录成功但课表空白 | 该账号从未同步过课表；先在 A 端添加课程并同步 |
| 旧共享码数据没迁移 | 跑迁移工具：`java -cp server\build\libs\timetable-server-all.jar com.example.timetable.server.MigrateToolKt timetables.json 你的邮箱` |
| 端口占用 | 关闭旧 `start-web.bat` 窗口再启动 |
