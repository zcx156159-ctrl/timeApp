| 项目 | 内容 |
|------|------|

---

## 1. 目标与范围

V2.0 把课表从“本地 + 裸共享码”升级为“账号 + 云端”：

1. 账号体系：注册/登录/刷新令牌，数据按用户隔离
2. 云端存储：从 JSON 文件迁移到数据库（开发 SQLite / 生产宝塔 MySQL）
3. 多课表：一人多份课表（本学期/下学期/工作）
4. 同步合并：字段级合并 + tombstone + 离线队列
5. 数据能力：导出/备份、注销删除
6. 共享权限：共享码支持只读/可编辑，可撤销
7. Web PWA 离线壳

**不在 V2.0**：微信登录（待企业资质）、群组协作、统计报表、云推送。

## 2. 后端技术方案

### 2.1 框架与分层

- 保留 Kotlin/JVM + JDK 内置 HttpServer（无需引入 Web 框架，控制复杂度），但**按层重构**：
  - `route/`：URL → handler 映射 + 统一响应/异常包装
  - `service/`：业务逻辑（账号、课表、同步、共享）
  - `repository/`：数据库访问
- 数据库访问：**Exposed**（JetBrains 官方 Kotlin ORM）+ JDBC 驱动
  - 开发：SQLite（`org.xerial:sqlite-jdbc`）
  - 生产：MySQL（`com.mysql:mysql-connector-j`）
  - 通过配置文件/环境变量切换，DDL 用 Exposed Schema 自动建表（两库方言兼容即可）
- 依赖（需联网下载）：Exposed 0.5x、mysql-connector-j、sqlite-jdbc、bcrypt（`at.favre.lib:bcrypt`）

### 2.2 统一响应与鉴权

- 统一响应：`{ "code": 0, "message": "ok", "data": ... }`；错误用 HTTP 状态码 + code
- 鉴权：`Authorization: Bearer <accessToken>`；JWT（HS256，密钥环境变量 `JWT_SECRET`）
  - access token：1 小时
  - refresh token：30 天，存数据库表 `refresh_tokens`，可吊销
- 限流：登录/注册/共享码接口按 IP 限流（内存滑动窗口即可）

## 3. 数据库设计（MySQL DDL 草案）

```sql
CREATE TABLE users (
  id            BIGINT AUTO_INCREMENT PRIMARY KEY,
  email         VARCHAR(255) UNIQUE,
  phone         VARCHAR(20)  UNIQUE,
  password_hash VARCHAR(100) NOT NULL,
  created_at    BIGINT NOT NULL,
  updated_at    BIGINT NOT NULL
);

CREATE TABLE refresh_tokens (
  id         BIGINT AUTO_INCREMENT PRIMARY KEY,
  user_id    BIGINT NOT NULL,
  token_hash VARCHAR(64) NOT NULL UNIQUE,
  expires_at BIGINT NOT NULL,
  revoked    TINYINT DEFAULT 0,
  FOREIGN KEY (user_id) REFERENCES users(id)
);

CREATE TABLE timetables (
  id           BIGINT AUTO_INCREMENT PRIMARY KEY,
  owner_id     BIGINT NOT NULL,
  name         VARCHAR(100) NOT NULL DEFAULT '我的课表',
  total_weeks  INT NOT NULL DEFAULT 20,
  current_week INT NOT NULL DEFAULT 1,
  start_date   DATE NULL,
  created_at   BIGINT NOT NULL,
  updated_at   BIGINT NOT NULL,
  FOREIGN KEY (owner_id) REFERENCES users(id),
  INDEX idx_timetables_owner (owner_id)
);

CREATE TABLE period_times (
  timetable_id BIGINT NOT NULL,
  period_no    INT NOT NULL,
  start_time   VARCHAR(5) NOT NULL,
  end_time     VARCHAR(5) NOT NULL,
  PRIMARY KEY (timetable_id, period_no),
  FOREIGN KEY (timetable_id) REFERENCES timetables(id)
);

CREATE TABLE courses (
  id           BIGINT AUTO_INCREMENT PRIMARY KEY,
  timetable_id BIGINT NOT NULL,
  sync_id      VARCHAR(36) NOT NULL,          -- 客户端生成的稳定 id
  name         VARCHAR(100) NOT NULL,
  teacher      VARCHAR(50)  NOT NULL DEFAULT '',
  location     VARCHAR(100) NOT NULL DEFAULT '',
  day          TINYINT NOT NULL,
  start_period TINYINT NOT NULL,
  end_period   TINYINT NOT NULL,
  color_index  INT NOT NULL DEFAULT 0,
  start_week   INT NULL,
  end_week     INT NULL,
  week_type    TINYINT NOT NULL DEFAULT 0,
  note         VARCHAR(255) NOT NULL DEFAULT '',
  updated_at   BIGINT NOT NULL,               -- 毫秒时间戳，同步用
  deleted      TINYINT NOT NULL DEFAULT 0,    -- tombstone
  FOREIGN KEY (timetable_id) REFERENCES timetables(id),
  UNIQUE KEY uq_timetable_sync (timetable_id, sync_id)
);

CREATE TABLE share_tokens (
  token        VARCHAR(16) PRIMARY KEY,
  timetable_id BIGINT NOT NULL,
  permission   VARCHAR(2) NOT NULL DEFAULT 'RO',  -- RO / RW
  created_by   BIGINT NOT NULL,
  revoked      TINYINT NOT NULL DEFAULT 0,
  created_at   BIGINT NOT NULL,
  FOREIGN KEY (timetable_id) REFERENCES timetables(id),
  FOREIGN KEY (created_by) REFERENCES users(id),
  INDEX idx_share_timetable (timetable_id)
);

CREATE TABLE exams (
  id           BIGINT AUTO_INCREMENT PRIMARY KEY,
  timetable_id BIGINT NOT NULL,
  name         VARCHAR(100) NOT NULL,
  exam_date    DATE NOT NULL,
  start_time   VARCHAR(5) NULL,
  location     VARCHAR(100) NOT NULL DEFAULT '',
  note         VARCHAR(255) NOT NULL DEFAULT '',
  FOREIGN KEY (timetable_id) REFERENCES timetables(id)
);
```

> 客户端 `Course` 现有 JSON 字段与 `courses` 表一一对应；`sync_id` 使用客户端原 `id`（如 `c3f...`），保证多端同一条目。

## 4. 账号接口（/api/v1）

| 方法 | 路径 | 说明 | 鉴权 |
|------|------|------|------|
| POST | /auth/register | 注册：`{email 或 phone, password}`（>=6 位）；校验邮箱/手机号格式 | 否 |
| POST | /auth/login | 登录，返回 `{accessToken, refreshToken, user}` | 否 |
| POST | /auth/refresh | 用 refreshToken 换新 accessToken | 否 |
| POST | /auth/logout | 吊销 refreshToken | 是 |
| DELETE | /users/me | 注销账号：删除用户及其所有课表数据 | 是 |
| GET | /users/me | 当前用户信息 | 是 |
| POST | /auth/wechat | 微信登录（预留接口，返回 501 待资质） | 否 |

注册/登录限流：每 IP 每分钟 5 次；密码错误统一返回 401（不区分“用户不存在/密码错误”）。

## 5. 课表与多课表接口

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | /timetables | 我的课表列表 |
| POST | /timetables | 创建课表 `{name, totalWeeks, currentWeek, startDate}` |
| GET | /timetables/{id} | 课表详情 + 课程列表 + 节次时间 |
| PUT | /timetables/{id} | 更新课表配置 |
| DELETE | /timetables/{id} | 删除课表（级联删课程） |
| PUT | /timetables/{id}/periods | 更新节次时间表 |

权限规则：仅 owner 可读写；共享 RW 可写课程但不可改课表配置/删除。

## 6. 同步接口（合并策略）

`POST /timetables/{id}/sync`

请求：
```json
{
  "upserts": [ {Course 完整字段, 含 updatedAt} ],
  "deletes": [ "sync_id1", "sync_id2" ],
  "clientUpdatedAt": 1720000000000
}
```

响应：
```json
{
  "changes": [ {Course 或 tombstone, updatedAt} ],
  "serverUpdatedAt": 1720000001000
}
```

合并规则（v1 保守策略）：
- 同一 `sync_id`：取 `updatedAt` 较大者（字段级仍以整条课程为准，后续可细化字段合并）
- 服务端只返回“比客户端 `clientUpdatedAt` 新”的变更，减少流量
- 删除用 tombstone（`deleted=1`），客户端本地据此清理
- 离线：客户端本地先写库并标记 dirty，联网后批量调用 `/sync`

## 7. 共享接口

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | /shares | 生成共享码 `{timetableId, permission}` → 6 位 token |
| GET | /shares/{token} | 查看共享信息（课表名、权限） |
| DELETE | /shares/{token} | 撤销共享（仅创建者） |
| GET | /public/timetables/{token} | 免登录只读获取课表（订阅链接用） |
| PUT | /public/timetables/{token}/courses | 免登录写入（仅 RW token） |

加入共享码的流程：客户端“加入共享”= 拉取 `/public/timetables/{token}` 数据，导入为“只读副本”或订阅视图（不复制到自己的 courses）。

## 8. 数据迁移（现状 → V2.0）

1. 现有 `timetables.json`（共享码 → 课程）导出为迁移脚本输入
2. 迁移工具：为每个共享码创建 `timetable`，owner 绑定到一个“迁移账号”（或用户登录后认领）
3. 客户端本地 JSON 数据：首次登录后提示“导入本地课表”→ 上传为新 timetable
4. 迁移前备份 JSON 文件；迁移可重复执行（幂等）

## 9. 客户端改造点

- `TimetableState`：多课表结构 `List<Timetable>`，当前课表切换；本地存储仍用 multiplatform-settings（JSON），但按 timetable 分组 + 每条 Course 带 `updatedAt`（V2.0 先不引入 SQLDelight，V2.1 评估）
- `CloudRepository`：改为 JWT 请求头 + 新 `/api/v1` 接口；登录态持久化（token 存 settings）
- 登录/注册页、我的课表（列表/切换/新建/重命名/删除）、共享管理页、设置页加“账号”
- 同步：启动拉取 → 合并 → 上传；编辑即标记 dirty，联网自动推
- Web 端：PWA（manifest + Service Worker 缓存壳与最近数据）

## 11. 风险

| 风险 | 缓解 |
|------|------|
| JWT 密钥/安全 | 密钥走环境变量；refresh token 可吊销；HTTPS |
| 同步合并丢数据 | 保守“后写覆盖 + tombstone”；冲突日志 |
| 数据迁移失败 | 迁移前备份；幂等可重跑 |
| Exposed 方言差异（SQLite/MySQL） | DDL 用 Exposed Schema 生成，双库冒烟测试 |
| bcrypt 依赖 | 成熟库 `at.favre.lib:bcrypt`，仅后端使用 |
